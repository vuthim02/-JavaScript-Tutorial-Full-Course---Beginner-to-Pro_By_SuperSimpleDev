# 📝 PART 1: WIREFRAMING

> **"Measure twice, cut once"** - Plan before you build!

---

### 🤔 What is a Wireframe?

A **low-fidelity visual representation** of your website/app layout using simple shapes and lines.

```
┌─────────────────────────────────────┐
│  [LOGO]     Menu    Menu    Menu    │  ← Header
├─────────────────────────────────────┤
│                                     │
│     ╔═══════════════════════╗       │
│     ║   HERO IMAGE/SLIDER  ║       │  ← Hero Section
│     ╚═══════════════════════╝       │
│                                     │
├─────────────────────────────────────┤
│  ┌─────┐  ┌─────┐  ┌─────┐        │
│  │ IMG │  │ IMG │  │ IMG │        │  ← Content
│  └─────┘  └─────┘  └─────┘        │
├─────────────────────────────────────┤
│  © Footer | Contact | Social       │  ← Footer
└─────────────────────────────────────┘
```

---

### 🎯 Why Wireframe?

| Benefit | Description |
|---------|-------------|
| ⚡ **Fast** | Quick visualization of structure |
| 💡 **Planning** | Plan before coding |
| 📄 **Documentation** | Living docs for team |
| 🔄 **Iterative** | Easy to modify |
| ⏰ **Time Saver** | Prevents costly changes later |

# 🔧 PART 2: PROTOTYPING

> **Build on your wireframe with real content (but no colors yet!)**

---

### 🤔 What is a Prototype?

A **medium-fidelity mockup** built on top of a wireframe with real text and structure.

| Aspect | Wireframe | Prototype |
|--------|-----------|-----------|
| 📊 **Detail** | Low-fidelity | Medium-fidelity |
| 📝 **Content** | Shapes/lines | Real text |
| 🎯 **Purpose** | Structure planning | Layout refinement |
| ⏱️ **Time** | Minutes-hours | Hours |

---

### 🛠️ Prototype #1: Early Setup

**Goal:** Build visually without color or images

```
Steps:
1️⃣ Reference your wireframe
       ↓
2️⃣ Set up grid structure in Figma
       ↓
3️⃣ Define frames and sections
       ↓
4️⃣ Add real content
```

---

### 📐 Prototype #2: Grid Structure

**Standard Web Grid System:**

```
┌─────────────────────────────────────────────────────────┐
│  ◀───────────── 1440px (Frame Width) ──────────────▶   │
│                                                         │
│  ┌─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┬─┐                          │
│  │1│2│3│4│5│6│7│8│9│0│1│2│  ← 12 Columns              │
│  └─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┴─┘                          │
│  ◀────────── 1140px (Content Width) ──────────▶       │
│                                                         │
│  Margin: 15-30px between grid units                     │
└─────────────────────────────────────────────────────────┘
```

**Figma Grid Setup:**
1. Create frame (1440px width)
2. Add layout grid
3. Set to columns
4. Configure 12 columns with spacing

⚠️ **Remember:** Design with developers in mind!

# 🎨 DESIGN PRINCIPLES

---

### 🌈 Color Theory Basics

**Color Relationships:**
```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   🔵 PRIMARY          🟢 SECONDARY       🟡 ACCENT      │
│   Main brand color    Complementary     Highlights/CTAs │
│                                                         │
│   ⚪ NEUTRALS                                          │
│   Grays, whites, blacks for backgrounds and text       │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

**Contrast Guidelines:**
| Element | Minimum Ratio |
|---------|---------------|
| 📝 Text on background | **4.5:1** |
| 📝 Large text | **3:1** |

**Tools:** WebAIM Contrast Checker

---

### 🔤 Typography Hierarchy

**Standard Scale:**
```
┌─────────────────────────────────────┐
│  Display: 48px / Bold               │  ← Biggest
├─────────────────────────────────────┤
│  H1: 36px / Bold                    │
├─────────────────────────────────────┤
│  H2: 28px / Semibold                │
├─────────────────────────────────────┤
│  H3: 22px / Medium                  │
├─────────────────────────────────────┤
│  Body Large: 18px / Regular         │
├─────────────────────────────────────┤
│  Body: 16px / Regular               │  ← Standard
├─────────────────────────────────────┤
│  Small: 14px / Regular              │
├─────────────────────────────────────┤
│  Caption: 12px / Regular            │  ← Smallest
└─────────────────────────────────────┘
```

**Font Pairing Tips:**
- 🔤 Use **2-3 fonts** maximum
- 🔀 Pair **serif** with **sans-serif**
- 👁️ Ensure readability at all sizes
- 🎨 Consider brand personality

---

### ↔️ Spacing & Layout

**The 8px Grid System:**
```
Base: 8px
8 → 16 → 24 → 32 → 40 → 48 → 56 → 64 → ...
```

**White Space:**
- ✓ Don't fear empty space
- ✓ Improves readability
- ✓ Creates visual hierarchy
- ✓ Guides user attention

---

### 👁️ Visual Hierarchy

**Principles (in order of impact):**

```
1️⃣ SIZE        → Larger = More attention
2️⃣ COLOR       → Bright/contrasting = Stands out
3️⃣ POSITION    → Top-left gets most attention (LTR)
4️⃣ WHITESPACE  → Isolation = Focus
5️⃣ TYPOGRAPHY  → Bold/heavy = Commands attention
```

# 👥 USER EXPERIENCE (UX) PRINCIPLES

---

### 📋 Usability Heuristics (10 Rules)

```
╔═══════════════════════════════════════════════════════════════╗
║  1️⃣  VISIBILITY OF SYSTEM STATUS                             ║
║      Show what's happening, progress indicators              ║
╠═══════════════════════════════════════════════════════════════╣
║  2️⃣  MATCH BETWEEN SYSTEM AND REAL WORLD                     ║
║      Use familiar language, follow conventions               ║
╠═══════════════════════════════════════════════════════════════╣
║  3️⃣  USER CONTROL AND FREEDOM                                ║
║      Easy undo/redo, clear exit points                       ║
╠═══════════════════════════════════════════════════════════════╣
║  4️⃣  CONSISTENCY AND STANDARDS                               ║
║      Consistent UI patterns, platform conventions            ║
╠═══════════════════════════════════════════════════════════════╣
║  5️⃣  ERROR PREVENTION                                        ║
║      Prevent errors before they occur                        ║
╠═══════════════════════════════════════════════════════════════╣
║  6️⃣  RECOGNITION RATHER THAN RECALL                          ║
║      Visible options, contextual help                        ║
╠═══════════════════════════════════════════════════════════════╣
║  7️⃣  FLEXIBILITY AND EFFICIENCY OF USE                       ║
║      Keyboard shortcuts, customization                       ║
╠═══════════════════════════════════════════════════════════════╣
║  8️⃣  AESTHETIC AND MINIMALIST DESIGN                         ║
║      Remove unnecessary elements, focus on essentials        ║
╠═══════════════════════════════════════════════════════════════╣
║  9️⃣  HELP USERS RECOGNIZE & RECOVER FROM ERRORS              ║
║      Clear error messages, suggest solutions                 ║
╠═══════════════════════════════════════════════════════════════╣
```

# 📱 RESPONSIVE DESIGN

---

### 📱 Mobile-First Approach

**Why mobile-first:**
- 🎯 Forces content prioritization
- ✅ Ensures core functionality works
- 📈 Easier to scale up than down
- ⚡ Better performance on mobile

**Implementation:**
```
1️⃣ Design for smallest screen first
       ↓
2️⃣ Add complexity for larger screens
       ↓
3️⃣ Use CSS media queries
       ↓
4️⃣ Test on real devices
```

---

### 📐 Breakpoint Strategy

**Common Breakpoints:**
```css
/* Mobile First Approach */

/* Base styles: mobile */
.container { width: 100%; }

/* Tablet */
@media (min-width: 768px) {
  .container { max-width: 720px; }
}

/* Desktop */
@media (min-width: 1024px) {
  .container { max-width: 960px; }
}

/* Large Desktop */
@media (min-width: 1200px) {
  .container { max-width: 1140px; }
}
```

---

### 🔄 Responsive Patterns

| Pattern | Description |
|---------|-------------|
| **Column Drop** | Elements stack vertically on mobile |
| **Layout Shifter** | Different layouts for different sizes |
| **Mostly Fluid** | Content flows, minor layout changes |

# 📌 IMPORTANT TAKE NOTES

---

### 🧠 Core Design Principles to Remember

```
╔═══════════════════════════════════════════════════════════════╗
║  1️⃣  DESIGN PROCESS ORDER                                   ║
║      Wireframe → Prototype → Design                          ║
║      ⚠️ NEVER skip steps!                                   ║
╠═══════════════════════════════════════════════════════════════╣
║  2️⃣  TIME INVESTMENT RULE                                   ║
║      Spend more time planning to save time later             ║
╠═══════════════════════════════════════════════════════════════╣
║  3️⃣  ALWAYS MOBILE-FIRST                                    ║
║      Start with smallest screen, scale up                    ║
╠═══════════════════════════════════════════════════════════════╣
║  4️⃣  GROUP EVERYTHING                                       ║
║      Always organize into labeled sections/groups             ║
╠═══════════════════════════════════════════════════════════════╣
║  5️⃣  REAL CONTENT EARLY                                     ║
║      Use actual text in prototypes, not placeholders          ║
╠═══════════════════════════════════════════════════════════════╣
║  6️⃣  GRID SYSTEM IS KING                                    ║
║      Always use 12-column grid (1140px width)                ║
╠═══════════════════════════════════════════════════════════════╣
║  7️⃣  LOGO DICTATES DESIGN                                   ║
║      Colors, style, typography come from the logo            ║
╠═══════════════════════════════════════════════════════════════╣
║  8️⃣  WHITE SPACE IS YOUR FRIEND                             ║
║      Don't fill every pixel - breathing room helps           ║
╠═══════════════════════════════════════════════════════════════╣
║  9️⃣  CONSISTENCY IS KEY                                     ║
║      Reuse components, maintain spacing, follow patterns     ║
╠═══════════════════════════════════════════════════════════════╣
║  🔟  THINK LIKE A DEVELOPER                                 ║
║      Design with implementation in mind                      ║
╚═══════════════════════════════════════════════════════════════╝
```

---

### ❌ Common Mistakes to Avoid

| Mistake | ❌ Why It's Bad | ✅ Solution |
|---------|----------------|-------------|
| Skipping wireframe | Wastes time fixing layout later | Always sketch first |
| Using lorem ipsum | Doesn't show real content fit | Use actual text |
| No mobile version | Loses mobile users | Create responsive wireframe |
| Not grouping elements | Hard to move/modify sections | Group + label everything |
| Too many fonts | Looks unprofessional | Max 2-3 fonts |
| Poor contrast | Accessibility issues | Check 4.5:1 ratio minimum |
| Ignoring developer handoff | Design can't be implemented | Export assets, provide specs |
