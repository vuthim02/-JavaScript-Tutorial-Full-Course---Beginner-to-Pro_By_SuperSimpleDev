# ES2025 / ES2026: New JavaScript Features

## `Array.fromAsync` (ES2024, shipped 2025)

Async version of `Array.from` — creates an array from an async iterable or promise-returning map function:

```javascript
async function* asyncGen() { yield 1; yield 2; yield 3; }
const arr = await Array.fromAsync(asyncGen());
console.log(arr); // [1, 2, 3]

const doubled = await Array.fromAsync([1, 2, 3], async x => x * 2);
console.log(doubled); // [2, 4, 6]
```

Pre-ES2025 you'd need `for await...of` with `push()`.

## Iterator Helpers (ES2025/2026)

Lazy `.map()`, `.filter()`, `.take()` and more — directly on any iterator. No intermediate arrays, no eager evaluation.

```javascript
const results = [1, 2, 3, 4, 5, 6]
  .values()
  .filter(x => x % 2 === 0)
  .map(x => x * 10)
  .take(2)
  .toArray();

console.log(results); // [20, 40]
```

### Available Methods

| Method | Returns | Description |
|--------|---------|-------------|
| `.map(fn)` | Iterator | Transform each value |
| `.filter(fn)` | Iterator | Keep values passing predicate |
| `.take(n)` | Iterator | First `n` values |
| `.drop(n)` | Iterator | Skip first `n` values |
| `.flatMap(fn)` | Iterator | Map then flatten one level |
| `.reduce(fn, init)` | Value | Aggregate to single value |
| `.toArray()` | Array | Collect all values |
| `.forEach(fn)` | undefined | Side-effect per value |
| `.some(fn)` | boolean | Any value passes? |
| `.every(fn)` | boolean | All values pass? |
| `.find(fn)` | Value | First passing value |

### Lazy Evaluation in Action

```javascript
function* infinite() { let i = 0; while (true) yield i++; }

const firstFiveEven = infinite()
  .filter(x => x % 2 === 0)
  .map(x => x * 10)
  .take(5)
  .toArray();

console.log(firstFiveEven); // [0, 20, 40, 60, 80]
// No infinite loop — filter/map/take are lazy
```

### Converting to Iterator

```javascript
// Arrays: .values()
[1, 2, 3].values().map(x => x * 2);

// Maps/Sets: .keys(), .values(), .entries()
new Map([[1, 'a']]).values().take(1);

// Any iterable: Iterator.from()
Iterator.from(document.querySelectorAll('a'))
  .filter(el => el.href)
  .map(el => el.href)
  .take(10)
  .toArray();
```

### Performance: Lazy vs Eager

```javascript
// Eager — creates 3 intermediate arrays
const eager = arr.filter(f1).map(f2).slice(0, 10);

// Lazy — single pass, constant memory
const lazy = arr.values().filter(f1).map(f2).take(10).toArray();
```

For large datasets (CSV parsing, paginated APIs, infinite generators), the lazy version uses O(1) memory. The eager version builds three throwaway arrays.

### When NOT to use

- Small arrays (< 100 items) — overhead of iterator protocol isn't worth it
- Multiple passes — iterators are single-use
- Hot-path loops — plain `for` is still faster

## Pattern Matching (Stage 4, June 2026)

Destructuring-powered switch that matches on shape, not just value:

```javascript
match (value) {
  when ({ type: "user", name }) -> `Hello, ${name}`;
  when ({ type: "admin", role }) -> `Admin (${role})`;
  when ({ status: "error", message }) -> `Error: ${message}`;
  when (null) -> "Nothing";
  default -> "Unknown";
}
```

### Key Features

| Feature | Behavior |
|---------|----------|
| **when** clauses | Tried in order — first match wins |
| **Binding** | Variables capture matched values |
| **Guards** | `when (x) if x > 0 -> ...` |
| **Nesting** | Match on deeply nested data |
| **Exhaustiveness** | `default` required unless all cases covered |

```javascript
function describe(shape) {
  return match (shape) {
    when ({ kind: "circle", radius }) -> `Area: ${Math.PI * radius ** 2}`;
    when ({ kind: "rect", width, height }) -> `Area: ${width * height}`;
    default -> "Unknown shape";
  };
}
```

Replaces long `if/else` chains and error-prone `switch` with declarative, exhaustive matching.

## Records & Tuples (Stage 4, June 2026)

Immutable, value-equality data structures:

```javascript
const r1 = #{ x: 1, y: 2 };
const r2 = #{ x: 1, y: 2 };
console.log(r1 === r2); // true — value equality!

const t1 = #[1, 2, 3];
const t2 = #[1, 2, 3];
console.log(t1 === t2); // true
```

### Rules

- Values must be primitives or other Records/Tuples (no functions, Date, DOM nodes)
- Deeply frozen — no mutation possible
- `#{ x: 1 } === #{ x: 1 }` is `true` (value equality, ~175x faster than deep equality)

### Why They Matter

| Use Case | Before | After |
|----------|--------|-------|
| React memo | `React.memo(Comp, shallowEqual)` | `React.memo(Comp)` — value equality works |
| Redux selectors | `reselect` or deep equality | Inline `===` |
| Set/Map keys | Only strings/symbols reliably | Any Record/Tuple |

## `Promise.try()` (ES2026)

Wraps a sync-or-async callback so the result is always a `Promise`:

```javascript
// Before — need try/catch for sync, .catch for async
function run(fn) {
  try { return Promise.resolve(fn()); }
  catch (e) { return Promise.reject(e); }
}

// After
function run(fn) {
  return Promise.try(fn); // sync throw → rejected promise
}
```

Eliminates the try/catch boilerplate at async boundaries. Perfect for callback-based APIs, plugin systems, and higher-order functions.

## Temporal (Stage 4, March 2026)

`Date` replacement that's been in development for over a decade. Immutable, timezone-aware, nanosecond precision.

```javascript
// Plain date (no timezone)
const date = Temporal.PlainDate.from("2026-03-15");
date.add({ days: 7 }).toString(); // "2026-03-22"

// Zoned instant
const meeting = Temporal.ZonedDateTime.from({
  timeZone: "America/New_York",
  year: 2026, month: 6, day: 15, hour: 14,
});
meeting.toLocaleString(); // "6/15/2026, 2:00:00 PM EDT"

// Duration arithmetic
const work = Temporal.Duration.from({ hours: 8, minutes: 30 });
work.total("minutes"); // 510

// Comparison
Temporal.PlainDate.compare("2026-06-01", "2026-07-01"); // -1

// Timezone-safe difference
const start = Temporal.Instant.from("2026-06-01T00:00:00Z");
const end = Temporal.Instant.from("2026-06-15T00:00:00Z");
start.since(end).total("days"); // -14
```

### Key Types

| Type | Purpose |
|------|---------|
| `Temporal.Instant` | Fixed point in time (nanosecond precision) |
| `Temporal.ZonedDateTime` | Timezone-aware date+time |
| `Temporal.PlainDate` | Date without time/timezone |
| `Temporal.PlainTime` | Time without date/timezone |
| `Temporal.PlainDateTime` | Date+time without timezone |
| `Temporal.Duration` | Length of time for arithmetic |
| `Temporal.TimeZone` | IANA timezone wrapper |

### Migration from `Date`

| Operation | `Date` | `Temporal` |
|-----------|--------|------------|
| Current time | `new Date()` | `Temporal.Now.instant()` |
| Parse ISO | `new Date("2026-06-15")` | `Temporal.PlainDate.from("2026-06-15")` |
| Add days | `d.setDate(d.getDate()+7)` | `date.add({ days: 7 })` |
| Diff dates | Manual math | `a.since(b)` |
| Timezone safe | Moment/Luxon needed | Built-in |

## Decorators (Stage 4, March 2026)

TC39 Decorators (not TypeScript's experimental version):

```javascript
function logged(target, context) {
  const methodName = String(context.name);
  const original = target;
  return function(...args) {
    console.log(`Calling ${methodName} with`, args);
    const result = original.call(this, ...args);
    console.log(`  → returned`, result);
    return result;
  };
}

class Calculator {
  @logged
  add(a, b) { return a + b; }
}

new Calculator().add(2, 3);
// Calling add with [2, 3]
//   → returned 5
```

### Key Differences from TypeScript Legacy

| Aspect | TS Legacy | TC39 Standard (2026) |
|--------|-----------|---------------------|
| Parameters | Multiple args, mutating | `(target, context)` |
| Return | Replaces descriptor | Replaces decorated element |
| Overhead | None measured | ~4.7% on hot paths |

Use for: logging, timing, validation, DI, serialization.

## Set Methods (ES2025)

```javascript
const a = new Set([1, 2, 3, 4]);
const b = new Set([3, 4, 5, 6]);

a.intersection(b); // Set { 3, 4 }
a.union(b);        // Set { 1, 2, 3, 4, 5, 6 }
a.difference(b);   // Set { 1, 2 }
a.symmetricDifference(b); // Set { 1, 2, 5, 6 }

a.isSubsetOf(b);      // false
a.isSupersetOf(b);    // false
a.isDisjointFrom(b);  // false
```

No more manual `filter` + `has` loops for basic set algebra.

## Smaller Features

### `RegExp.escape()` (ES2026)

```javascript
const userInput = "Hello (world)? [test]";
const escaped = RegExp.escape(userInput);
// "Hello \\(world\\)\\? \\[test\\]"
new RegExp(escaped).test("Hello (world)? [test]"); // true
```

Replaces the `escape-string-regexp` npm package. Always escape user input before passing to `new RegExp()`.

### `RegExp Modifiers` (ES2025)

Inline flag toggling within regex patterns:

```javascript
/hello (?i:world) test/; // case-insensitive only for "world"
/(?i:hello) (?-i:world)/; // "hello" case-insensitive, "world" case-sensitive
```

### `Float16Array` (ES2026)

```javascript
const f16 = new Float16Array([1.5, 2.25, 3.75]);
Math.f16round(3.14159); // 3.140625 — round to float16 precision
```

Critical for WebGPU shader data and ML model weights — halves memory vs Float32.

### JSON Modules (ES2025)

```javascript
// import data from "./config.json" with { type: "json" };
// Previously needed fs.readFile or fetch
// Static import with type assertion — no runtime parsing needed
```

## Reverse Engineering Questions

| Question | Answer |
|----------|--------|
| How do Iterator Helpers differ from array methods? | Lazy — no intermediate arrays, single pass, O(1) memory |
| When should I use `.take()` over `.slice()`? | With generators or infinite sequences — slice requires an array |
| Does Pattern Matching replace `switch`? | Yes for shape-based matching; `switch` still fine for simple values |
| Why does `#{x:1} === #{x:1}` return true? | Value equality (structural), not reference identity |
| What breaks when adopting Records? | WeakMap keys, libraries that mutate props |
| How does `Promise.try()` differ from `Promise.resolve()`? | `try()` catches sync throws and returns rejected promise |
| Should I migrate from `Date` to `Temporal`? | Yes for new code — Temporal is immutable, timezone-safe, nanosecond precision |
| Are Decorators same as TypeScript experimental? | No — different API `(target, context)`, different behavior |
| What's the catch with Iterator Helpers? | Single-use iterators, overhead on small datasets |
| When to use `RegExp.escape()`? | Always when constructing regex from user input or dynamic strings |
